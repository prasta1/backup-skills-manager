# SMB mount & keychain quirks (macOS Studio ↔ MacBook / NAS)

- Finder-created SMB keychain items are ACL-blocked for `security` CLI and `smbutil`: a failed CLI read does **not** mean no password is stored. Finder itself reads them fine — test through Finder.
- `smbutil view -g` authenticates as **guest**, not from keychain. For a keychain attempt use `smbutil view //user@host` (no flag).
- Finder's credential cache survives unmounts and can silently remount (no prompt) for a while — a "successful mount" in that state proves nothing about persistence. To validate durable keychain-only recovery: `diskutil unmount`, confirm `smbutil statshares -a` shows no session for that server, `killall Finder` (Finder auto-restarts; existing mounts like tanker survive), then `osascript -e 'mount volume "smb://user@server/share"'`. Silent return in ~1s = keychain works; a login sheet that hangs the call = bad/unusable item.
- The Finder auth sheet defaults **"Remember this password" OFF**. An unattended/unchecked connect authenticates but stores nothing. Verify storage with metadata-only `security find-internet-password -s <server>` (fresh `cdat`, correct `acct`) — that read never prompts.
- Bind SMB credentials to the tailnode **IP**, not the `<machine>.<tailnet>.ts.net` name: machine-name churn orphans keychain items (that broke the MacBook remount agent for days in Oct 2026). If the MBP's tailnet IP changes, both the keychain item and the agent URL need redoing.
- Remount agent `local.smb-mount.macbook` (GUI launchd, 300s interval; renamed 2026-10-13 from `dev.pdwerx.mount-macbook` — nothing referenced the old label, rename was label+filename+reload): `mount | grep -q ' /Volumes/prasta ' || osascript -e 'mount volume "smb://prasta@100.68.81.83/prasta"'`. Mount-point grep pattern needs the literal leading/trailing spaces. (The old `dev.pdwerx.*.bak` from the Oct 2 edit was deleted 2026-10-13 — it carried the stale label + pre-fix ts.net URL; no backups of this agent remain, the live plist is the only source.)
- `/Volumes` is root-owned: a user shell cannot pre-create mount dirs, so `mount_smbfs` CLI fails with "could not find mount point" for network volumes. Mount through Finder (`osascript 'mount volume ...'`) — it has a privileged helper.
- Editing launchd `ProgramArguments`: use `plutil -replace ProgramArguments.N -string ...` — **PlistBuddy `Set` strips nested quotes** and silently corrupts shell one-liners. After any edit: `bootout` + `bootstrap`, then verify by extracting the string and running it in a safe no-op state.
- Before calling a timestamp wrong/futuristic, check `date -u` against the peer host — long diagnostic sessions consume more wall-clock than perceived; "future" file mtimes were correct.
