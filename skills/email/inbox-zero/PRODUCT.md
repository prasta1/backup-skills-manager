# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

A single user: Patrick, working at his desk on the Mac Studio, clearing a Gmail
inbox that accumulates months of promotional, newsletter, and notification mail
alongside a small number of messages that actually matter.

## Product Purpose

A single-page browser widget that groups the Gmail inbox by sender and lets
Patrick archive, mark as read, or delete mail in bulk — reaching literal inbox
zero, where every message has been triaged. Generated by
`scripts/build_inbox_widget.py` from a live `himalaya` inbox enumeration, opened
in the MacBook browser; a local server (`scripts/inbox-delete-server.py`) performs
the actual Gmail actions.

## Positioning

The differentiator is the sender-grouped triage surface with in-browser
destructive actions: rather than a mail client's chronological list, the widget
collapses hundreds of messages into named senders, so one decision clears a whole
sender's history. No neighboring mail client organizes bulk triage this way.

## Operating Context

- Runs on the MacBook (the browser that opens it); the delete server runs on the
  same machine, because the Studio's application firewall drops inbound to new
  Python processes.
- The inbox is enumerated from the Studio via `himalaya` (account `gmail`); the
  MacBook's himalaya account is `personal`.
- Actions map to himalaya: delete -> trash, archive -> `[Gmail]/All Mail`,
  mark-read -> `seen` flag.
- Invoked periodically and on demand, not continuously — the server is a
  per-session background process, not a LaunchAgent.

## Capabilities and Constraints

- Sender-grouped list with clickable pills for high-count senders.
- Per-email rows (subject, date, unread state) that expand under a sender.
- Three bulk actions with double-click-to-confirm: Delete, Archive, Mark as read.
- Filter senders by search; select-all / clear.
- Deletes move to trash (recoverable ~30 days) — nothing is permanent.
- Undecided: whether the widget should also surface action-only items (bills,
  RSVPs) distinctly from pure noise.

## Evidence on Hand

Real data is the Gmail inbox itself (hundreds of messages, ~170 senders per run).
No testimonials, benchmarks, or marketing claims exist or should be invented. The
widget is a genuine working tool, not a demo.

## Product Principles

1. Every message reaches a terminal state — the surface exists to leave nothing
   untriaged.
2. Destructive actions are reversible and confirmed; the tool never makes
   permanent deletion one click away.
3. The sender is the decision unit; clearing a sender's history is one decision.
4. The tool disappears into the task — familiarity over novelty, no decoration
   that does not speed triage.

## Accessibility & Inclusion

Single-user personal tool; no accessibility standard was established as a hard
requirement. Keyboard focus and readable contrast remain good practice.
